# 農業データポータル 説明書

更新日：2026年11月15日(数字の確認日は2026年11月14日)
更新の周期：月に1回

## このサイトは何か
農林水産省をはじめ、日本銀行、総務省統計局、日本政策金融公庫などが公表している数字を、1か所で見られるようにするサイトです。
見せる相手は、農家さんと、会員企業(商社・メーカー)です。
数字ごとに、対象の時期、版(確定値・速報・予想など)、公表日、出典のリンク、数字が書かれていた原文を表示します。

## いまの状態
- 載せている数字は27件です。すべて、公表ページで確認して、手で data.json に写したものです。
- 月ごとに出る7項目(農産物価格指数、農業生産資材価格指数、生乳の生産量、米の相対取引価格、米の民間在庫量、企業物価指数、消費者物価指数)には「自動更新」の印が付いていて、自動で更新します(下の「自動更新」を参照)。そのほかの項目は、手で data.json を直します。
- 数字ごとに「最終確認」の日付を小さく載せています。新しい公表がなくても、確認した日に更新されます。
- 数字は、画面の上ではすべてアラビア数字(例：836,000)にそろえています。原文の引用だけは、出典の書き方のまま(例：83万6千)です。
- 画面の下の「出典カタログ」に、載せている統計の出典を並べています。

## ファイルの役割
- index.html：画面です。data.json を読んで表示します。
- data.json：数字・出典・原文の引用の一覧です。画面に出る内容は、すべてここにあります。
- check_data.py：data.json の数字が、原文の引用の中に本当にあるかを確かめます。漢数字が残っていないかも確かめます。
- sync_embedded.py：data.json の内容を、index.html の中の控えに写します。
- update_stats.py：公式のPDFから数字を読み取って、data.json を更新します(自動更新で使います)。
- update.html：数字を入れ替えるための更新画面です(下の「更新画面の使い方」を参照)。
- apply_update.py：更新画面から送られた内容を、data.json に反映します。
- remind.py：更新の時期が来た数字を、お知らせの文章にします。
- update.yml：毎週月曜の朝9時に、update_stats.py を動かす設定です。
- apply-update.yml：更新画面から送られた内容を、受け取って反映する設定です。
- remind.yml：毎月1日に、更新の時期のお知らせを出す設定です。
- (update.yml、apply-update.yml、remind.yml は、GitHub の .github/workflows/ に置きます)

## 数字を直す・足すときの手順
1. data.json を開き、数字を直す(足すときは、items に1件ぶんを足す)
2. 数字が書かれている原文を、quote に写す。出典の URL を source_url に入れる
3. 「python check_data.py」を実行する。「問題ありません」と出るまで直す
4. 「python sync_embedded.py」を実行する
5. GitHub に data.json と index.html をアップロードする(check_data.py と sync_embedded.py は、変えたときだけ)

## data.json の項目(1件ぶん)
- value：画面に出す数字(カンマ入り)。num：同じ数字(計算用)。qf：原文の単位に直す倍率(例：億円は100000000)
- unit：単位。delta：増減の文と向き(up・down・flat)。checks：増減の文に出てくる数字
- basis：対象の時期。version：版。version_note：この数字についての注意
- published：公表日(2026-10-30 の形)。公表日が出典に書かれていないときは null にして、published_note に理由を書く
- quote：数字が書かれていた原文。表の行を写したときは、quote_note に書く
- series：時系列(グラフ用)。breakdown：内訳。bars を true にすると、内訳が棒になる
- aud：見る人(農家・商社・メーカー)。cat：分野

## 数字の扱いの決まり
- 出典のページに書いてある数字だけを載せる。計算で出した数字や、予想は載せない。
- 数字は、原文の引用とセットで載せる。引用が取れないものは、載せない。
- 同じ統計に、概数値と確定値があるときは、確定値を主に出す。以前の版は、history に残す。
- 公表日が出典に書かれていないときは、推測で日付を入れず、その旨を書く。
- 報道の転載(二次情報)の数字は、載せない。

## 載せるときの注意(この版の確認で分かったこと)
- 原文の引用は、公表ページを読み取った結果です。PDFの紙面と一字一句同じとは限りません。公開する前に、数字の多い項目から、出典のページと見比べてください。
- 次の項目は、出典の書き方に注意が要ります。
  - 基幹的農業従事者・平均年齢：2025年までは全数調査、2026年は標本調査の推定値です。
  - 平均年齢・荒廃農地：表の行を写したもので、文章の引用ではありません。
  - 農業総産出額・生産農業所得：第1報か確報かが、出典に書かれていません。
  - 生乳の生産量：PDFで改行されていた文をつないでいます。
  - 肥料の物価指数と通関価格：ページの表から写しています。

## 自動更新
- 毎週月曜の朝9時(日本時間)に、GitHub が update_stats.py を動かします。新しい月の公表があれば、数字・原文・公表日・出典のリンクを入れ替えます。公表がなければ、数字は変えず、「最終確認」の日付だけを今日にします。
- 対象と、資料の探し方は次のとおりです。
  - 農産物価格指数、農業生産資材価格指数：農林水産省 農業物価指数のPDF(アドレスが月ごとに決まっている)
  - 生乳の生産量：農林水産省 牛乳乳製品統計のPDF(同上)
  - 米の相対取引価格、米の民間在庫量：農林水産省の報道発表(アドレスが公表日の日付で決まるので、日付を順に当てて探す)
  - 企業物価指数：日本銀行のPDF(アドレスが月ごとに決まっている)
  - 消費者物価指数：総務省統計局の公表ページのリンクをたどる(※作成時に、ページの形を確認できていません。うまく取れないときは、失敗で知らせます)
- 次のときは、data.json を書き換えず、GitHub の Actions が「失敗」になり、登録のメールに知らせが届きます。
  - 資料はあるが、決まった文を読み取れない(文の書き方が変わった)
  - 数字が、前回から大きく動いている(読み取りの間違いの疑い)
  - 資料に、対象の月の記載がない
  - 公表の時期(対象の月の翌々月の10日)を過ぎても、新しい月の数字が取れていない
  - 更新したあとの照合(check_data.py)が通らない
- 知らせが届いたら、出典の資料を見て、手で data.json を直します(下の手順)。直すと、次の週から、また自動で進みます。
- 失敗した項目があっても、ほかの項目の更新は保存されます。
- 公表日は、資料に書かれた日付か、報道発表のアドレスの日付だけを入れます。分からなければ、空にして、注意書きを出します。
- 手で動かすとき：GitHub の「Actions」→「統計の自動更新」→「Run workflow」。
- 試験の方法：STATS_FIXTURE_DIR に、資料の文章を入れたファイルを置くと、本物の代わりに読みます。

## 更新画面の使い方
サイトのアドレスの最後に「update.html」を付けると、更新画面が開きます(例: https://〇〇.pages.dev/update.html)。パスワードの代わりに、GitHub のログインが使われます。リポジトリの持ち主が送ったものだけが、反映されます。
1. 更新する数字を、一覧から選ぶ(「最終確認」が古い順に並んでいます)
2. 出典のページを見て、新しい公表がなく、数字が同じなら、「変わりなし(確認しました)」を押す。「最終確認」の日付だけが、今日になります
3. 数字が変わっていれば、出典のページから、数字が書かれている文をコピーして、「原文」に貼る。新しい数字、増減の向き、増減の文、対象の時期、版、公表日を入力する
4. 画面の確認に✗が残っていれば、直す(数字が原文にない、漢数字が残っている、など)。すべて✓になると、「GitHub に送る」が押せる
5. 「GitHub に送る」を押す。開いた GitHub の画面で、緑の「Submit new issue」を押す
6. 1~2分で、結果が Issue のコメントで返り、サイトの数字が変わる
- 原文は、漢数字のままで大丈夫です。画面に出る数字だけを、アラビア数字にします。
- 原文に書かれていない数字(自分で計算した数字)は、載せられません。
- 内訳(田・畑など)や、推移のグラフがある数字は、内訳の数字も入力します。推移のグラフには、新しい数字が自動で足されます。
- 確定値で数字が変わったときは、「以前の数字を、以前の版として残す」にチェックします。
- 内容が長くて、GitHub が内容を受け取れないときは、題名だけが入った状態で開きます。「内容をコピー」を押して、本文の欄に貼ってください。
- 間違えて反映したときは、もう一度、正しい数字で入れ替えます。
- 更新画面は、「自動更新」の数字にも使えます。自動で取れなかったときに、手で入れ替えられます。

## 更新時期のお知らせ
毎月1日に、公表の時期の目安(data.json の due_months)になった数字と、最終確認から330日以上たった数字があれば、GitHub の Issue(題名は「[更新時期] 2026年12月」など)で、メールが届きます。何もなければ、届きません。リンクを付けるには、data.json の site_url に、サイトのアドレス(例: https://〇〇.pages.dev)を入れます。

## 設定が必要なところ
- data.json の repo：GitHub のリポジトリ名(例: koujihatakeyama-dot/nouka-toukei)。更新画面のボタンが、ここを開きます
- data.json の site_url：サイトのアドレス。お知らせの中のリンクに使います

## 手で直すとき(更新画面を使わない方法)
1. 農林水産省の「公表予定」ページで、その月に出る統計を確認する
2. 数字が変わった項目を、出典のページで確認して、data.json を直す(quote も新しい原文に直す)
3. 「python check_data.py」を実行して、「問題ありません」と出るまで直す
4. 「python sync_embedded.py」を実行する
5. GitHub に data.json と index.html をアップロードする
- 月ごとに出る項目：農業物価指数、米の相対取引価格と民間在庫、生乳の生産量、消費者物価指数、企業物価指数。
- 年に1回の項目：畜産統計、輸出額、食料自給率、耕地面積、基幹的農業従事者、農業景況調査、農業産出額。

## 公開について
- 置き場所は、補助金ポータルとは別の GitHub リポジトリ(nouka-toukei)です。
- Cloudflare Pages に、新しい公開の設定(プロジェクト)を作ります。ビルドのコマンドは空にして、出力フォルダも空(ルート)にします。
- 画面には、検索に出にくくする設定(noindex)を入れています。見られなくする仕組みではありません。URL を知っていれば、誰でも見られます。
